# ポケモンフレンダ ピックバトル アプリ 仕様書 v1.3

> ポケモンフレンダの「ピック（カード）」に書かれた **ポケモン名 / タイプ / エネルギー値** の3つだけを使って、
> 幼稚園児でも自分ひとりで遊べて、それでいて「ポケモンバトルらしさ」を味わえるデジタル・バトルアプリ。
> **親の iPhone 1台**を子どもと交代で使って遊ぶ、ホーム画面に追加できる Web アプリ（PWA）。

## 1. コンセプト

| 項目 | 内容 |
| --- | --- |
| ターゲット | メイン: 4〜6歳（年中〜年長）／サブ: 一緒に遊ぶ保護者 |
| 動作環境 | **親の iPhone 1台**。Safari でホーム画面に追加して使う Web アプリ（PWA）。App Store を使わない |
| プレイ形態 | 1台の端末を親子で交代して使う「ホットシート方式」（対面プレイ） |
| 1バトルの長さ | 2〜7分（3vs3でも約7分） |
| 想定所持ピック数 | 20枚程度（一度登録したらデータベースに残り、次回からは選ぶだけ） |
| 読み書き前提 | **ひらがな・カタカナのみ**（漢字ゼロ）。読めなくても絵と音でわかる |
| 計算前提 | 足し算・引き算ができなくても遊べる（数値の増減はアプリが全部やる） |
| キモ | 「だれで こうげきするか選ぶ」「だれを ねらうか選ぶ」「サイコロを振る」の3アクションだけ |

### 設計の3原則

1. **えらぶのは2つだけ** — 「じぶんのポケモン」と「あいてのポケモン」。あとはサイコロを振るだけ。
2. **まちがえても損しない** — 選択は必ず取り消せる。理不尽な負け筋（0ダメージ・行動不能）は作らない。
3. **かならず盛り上がる山場がある** — ピンチのときにメガシンカで逆転できる。負けている側ほど強くなる設計。

## 3. ゲームルール

### 3.1 バトル準備

1. **人数をえらぶ** — 1vs1 / 2vs2 / 3vs3 の3種類。
2. **チームをえらぶ** — プレイヤー1 → プレイヤー2 の順に、ずかんから人数分のポケモンを選ぶ。
   - **「まえとおなじ」「おきにいりチーム」ボタンでワンタップ編成**できる（毎回選び直す手間をなくす）。
   - 相手の選択画面に移る前に「はい、つぎのひとにわたしてね」という**受け渡し画面**を挟む（覗き見防止 & 交代の合図）。
3. **コイントス** — **表が あか、裏が あお のコイン**を投げる。出た色のチームが先攻。
   - 色がそのままチームなので、「どっちが出るか当てる」より園児にわかりやすい。
   - 回転したあと、出た色でコインが塗られ「あおチームが さきばん！」と出る。

### 3.2 バトルフィールドの考え方（重要な設計判断）

**チーム全員が最初から場に出る「勢ぞろい方式」**を採用する。控え・交代の概念は持たない。

- 理由: 「攻撃する自分のポケモンと、攻撃対象の相手のポケモンを選ぶ」という要望を素直に実現できる。
- 理由: 「交代」は園児には損得の判断が難しく、ターンを消費する概念自体が理解しにくい。
- 理由: 3体が画面に並んでいる方が、自分の手持ちを見渡せて楽しい。
- 副次効果: 「弱った相手にトドメを刺す」「つかれていない子を使う」という、園児にも理解できる戦術が自然に生まれる。

```
   ┌─────────  あいて  ─────────┐
   │  [ピカチュウ]  [リザードン]  [カビゴン]  │   ← タップで攻撃対象を選ぶ
   ├──────────────────────────┤
   │        わざ ／ ゲージ          │
   ├──────────────────────────┤
   │  [フシギダネ]  [ゲンガー]   [ミミッキュ]  │   ← タップで攻撃するポケモンを選ぶ
   └─────────  じぶん  ─────────┘
```

#### 手番のプレイヤーが いつも手前

**いま攻撃する側のチームを いつも下（手前）に置く。** 手番が変わると上下が入れかわる。

- 一度、位置を固定して**対面で遊ぶ**形も試したが、**向かいに座ると文字が上下さかさま**で
  読みにくく、うまくいかなかった。
- そのため、**スマホを渡しながら交代して遊ぶ**形に戻した。
  自分の番になったら、自分のチームがいつも手前にある。
- 手番が変わるときは「つぎは 〇〇の ばん！ スマホを わたしてね」と出す。
- ラベルも「じぶん（あか）」「あいて（あお）」と、手番から見た言い方にする。

### 3.3 1ターンの流れ

| # | ステップ | 画面の動き | 誰がやる |
| --- | --- | --- | --- |
| 1 | こうげきするポケモンをえらぶ | 自分の生存ポケモンが光る → タップで選択。**つかれている子には 💤 が付き、選ぶと「はんぶんだけど いい？」と出る** | 手番プレイヤー |
| 2 | ねらうポケモンをえらぶ | 相手の生存ポケモンが光る → タップで選択。**「ばつぐん! +20」バッジが自動表示される** | 手番プレイヤー |
| 3 | サイコロをふる | サイコロを大きくタップ → 回転アニメ | 手番プレイヤー |
| 4 | ダメージけいさん | 出目 → ダメージ数値が飛んでいく演出（ばつぐんなら「+20」、つかれなら「はんぶん…」が表示） | 自動 |
| 5 | たいりょくバーがへる | バーが減るアニメ + 効果音 | 自動 |
| 6 | ひんしはんてい | 0になったら「たおれた！」演出 | 自動 |
| 7 | メガシンカはんてい | 条件を満たしたポケモンがいれば発動演出 | 自動 |
| 8 | つかれのこうしん | 攻撃した子に 💤 が付く／休んだ子の 💤 が消える | 自動 |
| 9 | こうたい | 「つぎは 〇〇のばん！」→ 端末を渡す | 自動 |

**ステップ1・2はいつでもやり直せる**（サイコロを振るまでは選択解除可能）。

### 3.4 こうげきの やりかた と ダメージ

**サイコロではなく「タイミング」**を既定にする。

#### なぜ変えたか

サイコロ方式は、プレイヤーの決めごとが「だれで・だれを」だけで、
**強さを決めるのは全部サイコロ**だった。子どもに「自分がやった」手ごたえがなく、
毎ターンまったく同じ手順がつづくため単調になっていた。上手くなる余地もない。

タイミング方式は **腕前**で決まるので、遊ぶほど上手くなり、
「安全にいく？ 狙う？」という決めごとが毎ターン生まれる。

#### 1回のこうげきの流れ

1. **わざを えらぶ** — タイプごとに名前がついている（§3.4.1）
   - **ふつうの わざ** … ねらう場所が ひろい／ちからは ふつう
   - **つよい わざ** … ねらう場所が せまい／ちからが 大きい
   - **メガわざ** … メガシンカ中だけ。ねらわずに **連打**（§3.4.2）
2. **ゲージを まんなかで とめる**（メガわざ は **連打してためる**）

```
ダメージ = わざの ちから × タイミング × メガシンカ + ばつぐんボーナス ÷ つかれ
```

| 要素 | 値 |
| --- | --- |
| わざの ちから | ふつう **110** ／ つよい **190** ／ メガわざ **150**（バトルの長さの設定で 0.7〜1.4倍） |
| タイミング | ぴったり **2倍** ／ ちかい **1倍** ／ はずれ **0.5倍** |
| メガシンカ中 | ちから **1.5倍** |
| ばつぐんボーナス | +20（設定で変更可） |
| つかれ | ÷2 |

- **はずれても 0にはならない**（半分は当たる）。園児が「なにも できなかった」体験をしないため。
- 表示は必ず**10の倍数**（端数は切り上げ）。

#### ねらう はば

まんなかからの ずれ が、この はば の中なら成功（ゲージ全体を 1 としたとき）。

| わざ | ぴったり | ちかい |
| --- | --- | --- |
| ふつう | ±0.12 | ±0.32 |
| つよい | ±0.06 | ±0.22 |

#### 3.4.1 わざの名前

タイプごとに「ふつう」「つよい」の2つの名前を持つ。
**実在のわざ名は使わず**、タイプが分かるやさしい ことば にしている。
「リザードンの だいばくえん！」と出るだけで、ぐっとポケモンらしくなる。

#### 3.4.2 メガわざ（れんだ）

メガシンカ中だけ えらべる、**ねらわなくていい わざ**。
「当たりやすくなるだけ」では メガシンカ の うれしさ が うすいので、
**遊び方そのものが変わる** わざ を用意した。

| 項目 | 内容 |
| --- | --- |
| つかえる とき | メガシンカ中のみ |
| そうさ | **3秒のあいだ ボタンを 連打**して ゲージをためる |
| 目標 | **20タップ**でマックス（つかれていると **28タップ**） |
| ダメージ | ちから150 × (1 + ゲージ) × メガシンカ1.5倍 |
| はずれ | **ない**。1つも たたけなくても 1倍は出る |

- マックスまで ためても、**つよいわざ の ぴったり ほどは 出ない**。
  ねらわなくていい ぶん、最大値は ひかえめ にしてある。
- **ねらう必要がないので、小さい子でも かならず何かは出せる**。
  タイミングが むずかしい子ほど、メガシンカ が うれしくなる。
- つかれていると 目標のタップ数が増える（つかれの あらわれかた を そろえている）。

#### サイコロ方式も残す

もとの「サイコロの出目 × ばいりつ」も**設定で選べる**ようにしてある（§4）。
どちらが楽しいか、実際に遊んで比べられる。

#### バトルの長さ（実測）

`python3 tools/balance-sim.py` で確認できる。園児の腕前を想定した値。

| 設定 | 1vs1 | 2vs2 | 3vs3 |
| --- | --- | --- | --- |
| さくさく | 約0.8分 | 約2.1分 | 約3.1分 |
| **ふつう（既定）** | **約1.2分** | **約2.6分** | **約4.0分** |
| じっくり | 約1.7分 | 約3.4分 | 約5.2分 |

もとのサイコロ方式では 3vs3 が約7分だったので、**ほぼ半分**になっている。

### 3.6 メガシンカ

バトル中の山場を作る、逆転のための仕組み。

| 項目 | 内容 | 設定変更 |
| --- | --- | --- |
| できる条件 | 自分のポケモンのたいりょくが **1/3 以下（デフォルト）**になること | 1/2 / 1/3 / 1/4 / つかわない |
| 発動 | **自動では発動しない。** 自分のターンのはじめに「〇〇は メガシンカ できる！」と聞かれ、**する / いまはしない を選ぶ** | — |
| 対象 | ずかん登録時に「メガシンカできる」にチェックを入れたポケモンのみ | — |
| 回数 | 1バトルにつき、そのポケモン1回だけ（元に戻らない） | — |
| 効果（タイミング） | **わざの ちからが 1.5倍**＋**ねらう ところが ひろくなる**（ぴったり1.5倍・ちかい1.2倍）＋**メガわざ が つかえる**（§3.4.2） | — |
| 見た目 | **かげ が つよそうな すがた に変わる**（とがった オーラ と つの が付く・§3.9） | — |
| 効果（サイコロ） | **サイコロが2個になる**（ダメージ期待値が2倍） | — |
| 演出 | 虹色の光の輪 → かげが大きくなる → 画面が白く光る → 「メガシンカ！」の大きな文字（約2.4秒） | — |

#### いつ聞かれるか

- 判定するのは**自分のターンのはじめ**。攻撃を受けた瞬間ではない。
- 「いまは しない」を選んでも、**次の自分のターンにまた聞かれる**（条件を満たしているかぎり）。
- 2体が同時にできるときは、**1体ずつ順番に**聞く。
- 「いまは しない」を選んだターンは、そのターン中はもう聞かない（何度も聞かれて先に進めなくなるのを防ぐ）。

自動発動をやめたのは、**「ここぞ」で自分で決める楽しさ**を残すため。とっておいて、つよい相手の番に合わせて使うといった遊び方ができる。

- 「本当にピンチになってから強くなる」＝発動が終盤に寄るため、**逆転の瞬間がクライマックスになる**。
- 選ぶのは「する / しない」の2択だけなので、園児でも迷わない。
- たいりょく300のポケモンなら、1/3設定で残り100以下（＝あと1〜2発で倒れる）で発動する。ギリギリ感が出る。
- 判定はダメージ適用の直後に行うため、**同じ攻撃でひんしになった場合はメガシンカしない**（0になったら発動せずに倒れる）。
- **ちょうど 1/3（たいりょく300で残り100）でも発動する**。判定は小数を使わず整数の比較で行う（§8.3）。
- 発動ラインを 1/2 にすると早めに発動して派手になり、1/4 にすると「ほぼ倒れる寸前」の大逆転演出になる。

### 3.7 つかれ（連続攻撃のペナルティ）

同じポケモンばかりで殴り続けられないようにして、**チーム全員を使う理由**をつくる仕組み。

#### ルール

- **攻撃したポケモンは「つかれた」状態になる**（カードに 💤 が付く）。
- **そのターンに攻撃しなかった（休んだ）ポケモンは、元気に戻る**。
- **つかれが とれるのは 休んだときだけ。** つかれたまま攻撃しても とれない。
- **戦える子が1体だけのときは つかれない。** 交代できないので、
  つかれても どうにもならず、ずっと 💤 が付いたままになってしまうため。
  仲間がたおれて1体になった時点で、ついていた つかれも消える。

#### つかれると どうなるか

| こうげきの やりかた | つかれの あらわれかた |
| --- | --- |
| **タイミング（既定）** | **ねらう ところが せまくなる**（ぴったり 0.5倍・ちかい 0.7倍）。ダメージは減らさない |
| サイコロ | ダメージが **半分**になる |

タイミング方式では、ダメージを一律に半分にするより
**「うまく当てにくい」**ほうがゲームらしく、当てられたときの うれしさ も残る。

実測では、つかれると **ぴったりが とれる割合が およそ半分**になる
（でたらめに止める場合 23.9% → 12.1%、ねらって止める場合 43.9% → 22.0%）。
体感ははっきり変わる。一方で **はずれても半分は当たる**ため、
勝ち負けそのものへの影響は小さい（交代して戦うと 2〜3% 早く決着する程度）。
園児には きびしすぎず、上手な人ほど差を感じられる効き方になっている。

```
                    こうげきした？
                   ┌─────┴─────┐
                 はい          いいえ（やすんだ）
                   │                │
            つかれてた？          げんき ✨
           ┌───┴───┐
      いいえ        はい
        │            │
   ぜんりょく!     はんぶん…
   → つかれる 💤   → げんき ✨
```

#### 遊びとしてどう効くか（サイコロ方式のとき）

| 人数 | 起きること |
| --- | --- |
| 1vs1 | 1体しかいないので **「ぜんりょく → はんぶん → ぜんりょく → …」の交互**になる。リズムが生まれ、単調さがなくなる |
| 2vs2 / 3vs3 | **順番に交代して攻撃すれば全員ずっと全力**で戦える。強い子ばかり使うと半分になるので、自然と全員を使うようになる |

シミュレーションでも、3vs3 で交代して戦うと **21.0ターン**、同じ子を連打し続けると **24.3ターン**と差が出る（ばいりつ×20）。**「交代したほうが早く勝てる」**という、園児にも体感できるご褒美になっている。

#### 表示

- つかれているポケモンのカードに 💤 マークと、少し眠そうな見た目（彩度を落とす）。
- つかれている子を選んだとき: 「つかれてるから はんぶんだよ。それでも いい？」と確認を出す（**選べなくはしない**。あえて選ぶのも自由）。
- 誰かが元気に戻ったとき: ✨ の小さな演出。

#### 設定でオフにできる

いちばん小さい子と遊ぶときは、判断すべきことが1つ増えるのが負担になり得る。**設定で「つかれ ルールを つかわない」を選べる**ようにする（デフォルトは「つかう」）。

### 3.8 勝敗

- 相手チームの**全ポケモンがひんし**になったら勝ち。
- 結果画面では「かった！」を大きく祝う一方で、**負けた側にも必ず「〇〇は さいごまで がんばった！」と MVP ポケモンを表示**する（最も多くダメージを与えたポケモン）。園児が泣かないための配慮。
- 「もういっかい」ボタンで同じチーム編成のまま即リマッチできる。

### 3.9 ポケモンの かげ（シルエット）

画面には**かげ だけ**を出す。

実物のピックが手もとにあるので、**画面の中に絵は要らない**。
名前とタイプと かげ があれば、どのピックのことか子どもには分かる。
（ポケモンのイラストは著作権上つかえない、という事情とも合っている。）

#### かたちは16種類

**まる / よつあし / にそく / つばさ / へび / さかな / むし / おばけ /
きょだい / とげとげ / ドラゴン / いわ / しょくぶつ / くらげ / ロボット / こうら**

- 色はタイプの色を暗くしたもの。かげでもタイプが分かる。
- かたちは**ピックごとに ずかん登録画面（S-3）で えらぶ**。
- えらばなければ名前から自動で決まり、同じポケモンならいつも同じ かげ になる。
- かげは**カード・チームえらび・ずかん・メガシンカの演出・バトル画面**のすべてで使う。
- **メガシンカ中は かげ が変わる。** 16種類それぞれを描き直すのではなく、
  どの かたち にも **とがった オーラ と つの** を足して、ひとまわり大きく見せる。
  1つの作りで16種類ぜんぶが つよそうな すがた になり、変身したことが ひと目で分かる。

> 以前は実物ピックの写真を撮って登録できるようにしていたが、
> 実物が手もとにある以上、撮る手間に見合わないため機能ごと外した。
> 保存ずみの写真はデータベースの更新時に消して容量を返す（§10.2）。

### 3.10 攻撃の演出

攻撃は**4つの段階**に分けて見せる。いっぺんに出さないことで、
「サイコロの目が大きい → はでな攻撃 → たくさん減った」という因果が園児にも追える。

| # | 見せるもの | 時間の目安 |
| --- | --- | --- |
| 1 | **ゲージを とめる／れんだ する** | 〜3秒 |
| 2 | **カットイン** — ななめの おび が走り、こうげきする子の かげ と わざの名前が大きく出る | ふつう0.7秒／つよい0.9秒／**メガわざ1.3秒** |
| 3 | **こうげきが 飛んでいく** — こうげきする子から ねらわれた子へ、タイプのしるしが飛ぶ | 約0.4秒 |
| 4 | **当たって はじける** — 輪が広がり、かけらが飛びちり、画面がタイプの色にそまる | 約0.9秒 |
| 5 | **ダメージの数** — 当たった場所に「-140」が大きく出て、ふわっと浮かぶ | タップするまで |
| 6 | **たいりょくが へる** — バーがアニメーションで減る | 約0.4秒 |

#### カットイン

わざを出す しゅんかん に、画面いっぱいの カットイン を はさむ。

- ななめの **おび** が左から走る（タイプの色 + くろ の2本）。
- 左から **こうげきする子の かげ**（白ぬき）、右から **「〇〇の △△！」** が滑りこむ。
- **つよい わざ ほど 長く**見せる。メガわざ は いちばん長い。
- かげ と 文字が かさならないよう、それぞれの はば を かぎり、長い わざ名 は折りかえす。

#### メガわざ の エフェクト

メガわざ だけ、**専用の はでな エフェクト**にする。

| | ふつうの わざ | メガわざ |
| --- | --- | --- |
| カットイン の おび | タイプの色 + くろ | **にじいろ の グラデーション** |
| 輪 | 1本（ばつぐんで2本） | **4本を ずらして かさねる** |
| はじける光 | なし | **にじいろ の 大きな 光** が回りながら広がる |
| かけら | タイプの かけら | タイプの かけら + **✨**、数は **2倍** |
| 画面の そまり | タイプの色 | **にじいろ** |

#### 演出を はでにした ぶん の 長さ

1回のこうげきの 演出は 約0.8秒 → **約2.0〜2.6秒**になった。
3vs3（約12ターン）で **20秒ほど長くなる**が、
「じみ」だった問題のほうが 遊びごこち に効くと判断した。
長すぎるようなら、カットインの時間を短くして調整する。

#### 演出はバトル画面ぜんたいに広げる

エフェクトを**カードの中に描かない**。カードは110px ほどしかなく、
中に描くと小さすぎて何が起きたのか分からないため。

- 演出は**バトル画面ぜんたいに重ねたレイヤー**に描く。
- こうげきする子のカードの中心から、ねらわれた子のカードの中心へ向かって飛ばす。
  **だれが だれを こうげきしたのか**が目で追える。
- 位置はカードの実際の座標を測ってから飛ばすので、1vs1 でも 3vs3 でもずれない。
- カード自身は**ゆれる**だけにする。

#### 表示する場所を分ける

中央のせまい場所にすべてを重ねると、**ばつぐん や つかれ の表示が出たときに
ダメージの数が見切れる**。そこで置き場所を分ける。

| 表示 | 場所 |
| --- | --- |
| サイコロの目 / ばつぐん / つかれて はんぶん | 画面の**中央**（せまいので小さめに） |
| **ダメージの数** | **当たったカードの上**（演出レイヤー・大きく） |

ダメージの数は、白でふちどった赤い文字にして、カードのどんな絵の上でも読めるようにする。

**たいりょくは、エフェクトが終わるまで減らさない。** そのため、
サイコロを振った時点ではダメージを計算するだけにして、
エフェクトが終わってから実際に当てる（§8.1）。

#### タイプごとのエフェクト

タイプそれぞれに、飛びちる かけら と 中心のしるし を用意する。
色はそのタイプの色を使う。

| タイプ | かけら / 中心 | タイプ | かけら / 中心 |
| --- | --- | --- | --- |
| ノーマル | 💫 / 💥 | エスパー | ✨ / 🔮 |
| ほのお | 🔥 / 🔥 | むし | 🌀 / 🐝 |
| みず | 💧 / 🌊 | いわ | 🪨 / 🗿 |
| でんき | ⚡ / ⚡ | ゴースト | 👁️ / 👻 |
| くさ | 🍃 / 🌿 | ドラゴン | ☄️ / 🐲 |
| こおり | ❄️ / 🧊 | あく | 🌑 / 🦇 |
| かくとう | 💢 / 👊 | はがね | ⚙️ / 🔩 |
| どく | 🫧 / ☠️ | フェアリー | 💗 / 🌸 |
| じめん | 🪨 / 🏜️ | ひこう | 💨 / 🌪️ |

絵文字を使うので、画像を用意せずに18タイプぶんを表現でき、オフラインでも動く。

#### ダメージが大きいほど はでになる

ダメージから「迫力」を1つの数値にして、見た目の各所に反映する。

```
迫力 = ダメージ ÷ 180   （0.35〜1.5 のあいだにおさめる）
```

| 迫力で変わるもの | 弱い攻撃（40ダメージ） | 強い攻撃（260ダメージ） |
| --- | --- | --- |
| かけらの数 | 7こ | 16こ |
| かけらの飛ぶ距離・大きさ | 小さい | 大きい |
| はじける輪の大きさ | 小さい | 大きい |
| カードのゆれ | 弱い | 強い |

サイコロの目・ばつぐん・メガシンカ・つかれ は**すべてダメージに現れる**ので、
ダメージ1つを見るだけで迫力が決まる。こうかばつぐんのときは、
黄色い輪をもう1つ重ねて特別感を出す。

> 「動きを減らす」設定の端末では、アニメーションを止める。

## 4. 設定（保護者向け）

バトルの手ざわりを調整できるようにする。設定画面（S-10）は**長押し3秒**で入る（園児が誤って触らないため）。

| 設定項目 | 選択肢 | デフォルト | 効果 |
| --- | --- | --- | --- |
| こうげきの やりかた | **🎯 タイミング** / 🎲 サイコロ | タイミング | 腕前できまるか、運できまるか |
| バトルの ながさ | さくさく / **ふつう** / じっくり | ふつう | わざの ちから と サイコロの ばいりつ を同時に決める |
| ばつぐんの ボーナス | 0 / +10 / **+20** / +40 / +60 | +20 | タイプを狙う楽しさの強さ |
| メガシンカ する タイミング | たいりょく 1/2 / **1/3** / 1/4 / つかわない | 1/3 | 逆転演出の起こる時期 |
| つかれ ルール | **つかう** / つかわない | つかう | 交代の戦略性の有無 |
| おと | オン / オフ | オン | 効果音 |
| よみあげ | オン / オフ | オン | 音声読み上げ |

- 各項目には「おすすめ」バッジを付け、**「おすすめに もどす」ボタン**を常設する（迷子にならないため）。
- 設定画面には、いまの設定での **3vs3 の目安プレイ時間**を表示する（例:「3たい3で やく7ふん」）。数値は §5 の表を内蔵の対応表として持つ。
- 設定は `settings` テーブルに保存し、次回起動時も維持される。

## 5. バランス検証

`python3 tools/balance-sim.py` で再現できる（各20,000試行）。条件: たいりょく150〜350、こうかばつぐん15.7%、メガシンカ保有率40%、1ターン20秒換算。

### 5.1 ダメージばいりつ別の所要時間（v0.3 のデフォルト設定＝つかれあり・交代して戦う場合）

| ばいりつ | 1vs1 | 2vs2 | 3vs3 | 3vs3の想定プレイ時間 |
| --- | --- | --- | --- | --- |
| ×10「じっくり」 | 平均13.5ターン | 平均25.5ターン | 平均37.9ターン（最大66） | 約13〜22分 |
| **×20「ふつう」（推奨）** | **平均7.2ターン** | **平均14.1ターン** | **平均21.0ターン（最大36）** | **約7分** |
| ×30「さくさく」 | 平均4.7ターン | 平均9.8ターン | 平均14.9ターン（最大29） | 約5分 |

要望のあった「出目×10」は 3vs3 で平均37.9ターン（最大66ターン）となり、園児の集中力が持たない。**×20 を推奨デフォルト**とし、×10 は「じっくり」設定として残す。

### 5.2 つかれルールの影響（ばいりつ ×20）

| 人数 | つかれ なし | つかれ あり・交代する | つかれ あり・同じ子を連打 |
| --- | --- | --- | --- |
| 1vs1 | 5.7ターン | 7.2ターン | 7.2ターン |
| 2vs2 | 12.4ターン | 14.0ターン | 15.7ターン |
| 3vs3 | 19.3ターン | 21.0ターン | 24.3ターン |

つかれルールでバトルは1〜2割長くなるが、**交代という戦術が生まれ、上手に戦うと早く勝てる**という納得感のある差になっている。

### 5.3 ばつぐんボーナスの効き具合

+20 は固定値なので、ダメージばいりつによって「効いている感」が変わる。

| ばいりつ | 1回の平均ダメージ | +20 の相対的な重み |
| --- | --- | --- |
| ×10 | 35 | +57%（かなり効く） |
| ×20 | 70 | +29%（ほどよい） |
| ×30 | 105 | +19%（ほぼ誤差） |

ばつぐんの発生率は 15.7% なので、**3vs3 1試合を通じた +20 の総効果は総たいりょくの約4%**にとどまる。狙いどおり「強すぎない」が、逆に**タイプを考えて狙う意味がほとんどなくなる**可能性がある。設定で +40 / +60 に上げられるようにしたのはこのため。プレイテストで物足りなければ、デフォルトを +40 に引き上げることを検討する。

## 6. 幼稚園児向け UX 要件

これは「あったら良い」ではなく**必須要件**として扱う。

| # | 要件 | 詳細 |
| --- | --- | --- |

| U-9 | 保護者用の入口を分ける | **ずかん とうろく はタイトルに大きく出す**（親子で一緒にやる楽しい作業のため）。一方で**設定は長押し3秒**、**ピックの削除は確認をはさむ**（園児が誤って壊さない） |

| U-11 | 一度登録したら二度と入力しない | ピックはデータベースに永続保存。バトル開始からサイコロを振るまでに文字入力は一切発生しない |
| U-12 | 状態はマークで伝える | つかれ 💤、メガシンカ 🌈、ひんし ✕ など、文字を読まなくても状態がわかる |

- 並べ替え: **よくつかう順（デフォルト）** / なまえ順 / つよさ順（エネルギー値）/ とうろくした順。
- 絞り込み: タイプ別（タイプアイコンをタップ）。
- 20枚程度なら見て選べるため、検索窓は設けない。

## 8. データモデル（TypeScript）

```ts
/** ポケモンのタイプ（本家18タイプ）。ピックには1つだけ書かれている */
type PokemonType =
  | 'ノーマル' | 'ほのお' | 'みず' | 'でんき' | 'くさ' | 'こおり'
  | 'かくとう' | 'どく' | 'じめん' | 'ひこう' | 'エスパー' | 'むし'
  | 'いわ' | 'ゴースト' | 'ドラゴン' | 'あく' | 'はがね' | 'フェアリー';

/** ずかんに登録された1枚のピック（データベースの永続エンティティ） */
interface Pick {
  id: string;              // uuid
  name: string;            // ポケモン名（カタカナ）
  type: PokemonType;
  energy: number;          // エネルギー値 = 初期たいりょく（150〜350程度）
  canMegaEvolve: boolean;
  silhouette?: SilhouetteShape;  // かげの かたち。未指定なら名前から自動できめる
  useCount: number;        // 使用回数（「よくつかう順」の並べ替えに使う）
  createdAt: number;
  updatedAt: number;
}

/** 保存しておいたチーム編成 */
interface TeamPreset {
  id: string;
  name: string;
  pickIds: string[];       // 1〜3件
  updatedAt: number;
}

/** バトル中のポケモンの状態（永続化しない、メモリ上のみ） */
interface BattlePokemon {
  pickId: string;
  name: string;
  type: PokemonType;
  maxHp: number;           // = Pick.energy
  hp: number;              // 0 になったら ひんし
  canMegaEvolve: boolean;
  megaEvolved: boolean;
  tired: boolean;          // つかれ（§3.7）
  damageDealt: number;     // MVP 判定用の累計与ダメージ
}

/** かげの形（§3.9） */
type SilhouetteShape =
  | 'まる' | 'よつあし' | 'にそく' | 'つばさ' | 'へび' | 'さかな' | 'むし' | 'おばけ'
  | 'きょだい' | 'とげとげ' | 'ドラゴン' | 'いわ' | 'しょくぶつ' | 'くらげ' | 'ロボット' | 'こうら';

type PlayerId = 'p1' | 'p2';

interface BattleState {
  teams: Record<PlayerId, BattlePokemon[]>;
  turnPlayer: PlayerId;
  turnCount: number;
  phase:
    | 'megaPrompt'      // メガシンカ する？ と聞いている
    | 'megaEvolving'    // メガシンカ の演出中
    | 'selectAttacker'
    | 'selectTarget'
    | 'rollDice'
    | 'attacking'       // 攻撃エフェクト中。まだ当たっていない
    | 'resolve'
    | 'handOff'
    | 'finished';
  selectedAttackerIndex: number | null;
  selectedTargetIndex: number | null;
  megaCandidateIndex: number | null;  // メガシンカできる自分のポケモン
  lastRoll: number[];      // 直近の出目（メガシンカ中は2要素）
  winner: PlayerId | null;
}

/** §4 の設定。すべて settings テーブルに永続化する */
type MegaThreshold = 'half' | 'third' | 'quarter' | 'off';

/**
 * 発動ラインは分数のまま持つ。小数にすると 300 × (1/3) が 99.999… になり、
 * たいりょくが ちょうど 1/3 のときに発動しなくなるため。
 */
interface Fraction { numerator: number; denominator: number }

const MEGA_THRESHOLD_RATIO: Record<MegaThreshold, Fraction | null> = {
  half: { numerator: 1, denominator: 2 },
  third: { numerator: 1, denominator: 3 },
  quarter: { numerator: 1, denominator: 4 },
  off: null,
};

interface Settings {
  damageMultiplier: 10 | 20 | 30;              // デフォルト 20
  superEffectiveBonus: 0 | 10 | 20 | 40 | 60;  // デフォルト 20
  megaThreshold: MegaThreshold;                // デフォルト 'third'
  fatigueEnabled: boolean;                     // デフォルト true
  soundEnabled: boolean;
  speechEnabled: boolean;
}

const DEFAULT_SETTINGS: Settings = {
  damageMultiplier: 20,
  superEffectiveBonus: 20,
  megaThreshold: 'third',
  fatigueEnabled: true,
  soundEnabled: true,
  speechEnabled: true,
};
```

### 8.1 ダメージ計算（仕様の中核）

```ts
/** 10の倍数に切り上げる（端数は子どもに有利な側へ） */
const ceilTo10 = (n: number) => Math.ceil(n / 10) * 10;

function calcDamage(
  attacker: BattlePokemon,
  target: BattlePokemon,
  rolls: number[],
  settings: Settings,
): { damage: number; isSuperEffective: boolean; isTired: boolean } {
  const diceSum = rolls.reduce((a, b) => a + b, 0);
  const isSuperEffective = TYPE_CHART[attacker.type].includes(target.type);
  const isTired = settings.fatigueEnabled && attacker.tired;

  let damage = diceSum * settings.damageMultiplier;
  if (isSuperEffective) damage += settings.superEffectiveBonus;
  if (isTired) damage = ceilTo10(damage / 2);

  return { damage, isSuperEffective, isTired };
}
```

- 振るサイコロの数 = `attacker.megaEvolved ? 2 : 1`
- **計算と適用は分ける。** サイコロを振った時点では計算だけして `phase: 'attacking'` に進み、
  攻撃エフェクトが終わってから `target.hp = Math.max(0, target.hp - damage)` を適用する（§3.10）
- `target.hp === 0` → ひんし

### 8.2 つかれの更新

攻撃を解決した直後に、**攻撃した側のチーム全員**について更新する。

```ts
function updateFatigue(team: BattlePokemon[], attacker: BattlePokemon, wasTired: boolean): void {
  for (const p of team) {
    // 攻撃した子: 全力だったらつかれる／つかれた状態で攻撃したなら元気に戻る
    // それ以外の子: 休んだので元気に戻る
    p.tired = p === attacker ? !wasTired : false;
  }
}
```

`wasTired` は §8.1 の `isTired`（＝攻撃前の状態）。設定でつかれルールがオフのときは呼ばない。

### 8.3 メガシンカ判定

```ts
function shouldMegaEvolve(p: BattlePokemon, settings: Settings): boolean {
  const ratio = MEGA_THRESHOLD_RATIO[settings.megaThreshold];
  if (ratio === null) return false;
  if (!p.canMegaEvolve || p.megaEvolved || p.hp <= 0) return false;  // ひんしなら発動しない

  // hp <= maxHp × (numerator / denominator) を、小数を使わずに判定する
  return p.hp * ratio.denominator <= p.maxHp * ratio.numerator;
}
```

```ts
/** 自分のターンのはじめに呼ぶ。見つかったら「メガシンカする？」と聞く */
function findMegaCandidateIndex(team: BattlePokemon[], settings: Settings): number | null {
  const index = team.findIndex((p) => shouldMegaEvolve(p, settings));
  return index === -1 ? null : index;
}
```

**自動では発動しない。** `shouldMegaEvolve` は「できる状態か」を返すだけで、
実際に進化させるのはプレイヤーが「する」を選んだときだけ（§3.6）。

## 9. iPhone / Web アプリ（PWA）としての実現性

**結論: App Store を使わず、Safari の「ホーム画面に追加」で十分に実現できる。** 審査もApple Developer Program の年会費も不要で、URL を共有するだけで配布できる。

### 9.1 実現性の確認

| 必要なこと | iPhone Safari での可否 |
| --- | --- |
| ホーム画面に置いてアプリのように全画面で起動 | ○ 「ホーム画面に追加」+ manifest の `display: standalone`。iOS 26 ではホーム画面に追加したサイトが既定で Web アプリとして開く |
| オフラインで動く | ○ Service Worker でアプリ本体をキャッシュ |
| ずかんをデータベースに保存 | ○ IndexedDB が使える |
| 効果音・読み上げ | ○ Web Audio API / Web Speech API（§9.4 の制約あり） |
| サイコロ | ○ タップで振る（端末を振る操作は §9.4 参照） |
| 通信・アカウント | 不要（完全オフライン） |

### 9.2 データが消えないか（最重要の確認事項）

Safari には、**7日間サイトを使わないとスクリプトから書き込んだデータ（IndexedDB を含む）を削除する**という仕様がある。20枚の登録が消えると致命的なので、以下で対策する。

1. **ホーム画面に追加して使えば、この7日ルールの対象外になる。** ホーム画面の Web アプリは Safari とは別扱いで、独自の使用日数カウンタを持つ。→ **初回起動時に「ホーム画面に追加」を案内する画面を必ず出す**（iOS は追加を促す標準APIがないため、手順を図で自作する）。
2. **`navigator.storage.persist()` を起動時に呼ぶ**（Safari 17 以降で対応）。自動削除からの保護を要求できる。ただし要求が通るとは限らないため、これだけに頼らない。
3. **バックアップ（書き出し / 読み込み）を必須機能とする**（§10.4）。端末の故障・機種変更・長期未使用のいずれでも復旧できる状態にしておく。
4. **写真は長辺512pxに縮小して保存**し、容量を抑える（iOS は空き容量が減ると古いデータから削除するため）。

> この3層（ホーム画面追加 / persist() / バックアップ）で、「20枚の再登録」という最悪のケースを避ける。

### 9.3 iPhone 縦持ちのレイアウト

もっとも狭い iPhone SE（375×667）でも 3vs3 の6体が収まることを前提に設計する。

```
┌───────────────┐  ← safe-area（上）
│ あいて               │
│ [A] [B] [C]          │  カード 約110×140px（3列）
├───────────────┤
│   メッセージ帯        │
│      🎲 サイコロ      │  約200px
├───────────────┤
│ [D] [E] [F]          │
│ じぶん               │
└───────────────┘  ← safe-area（下・ホームインジケータ）
```

- カード幅は `(画面幅 - 余白) / 3` ≒ 110px。**タップ領域 64px 以上**（U-2）を満たす。
- ポケモン名は最大6文字を目安に自動縮小。長い名前は「…」で省略し、選択時に全体を表示。
- 高さは `100vh` ではなく **`100dvh`** を使う（Safari のアドレスバー伸縮で崩れるのを防ぐ）。
- `env(safe-area-inset-*)` でノッチ／ホームインジケータを避ける。
- **縦持ち固定**（manifest の `orientation: portrait`）。横持ちは対応しない。

### 9.4 iOS 固有の実装上の注意

| 項目 | 対応 |
| --- | --- |
| 音が鳴らない | iOS は自動再生を禁止。**最初のタップで `AudioContext.resume()` を呼ぶ**。また本体の消音スイッチがオンだと鳴らないため、「おとが でないときは マナーモードを かくにんしてね」を設定画面に表示 |
| 読み上げ | `speechSynthesis` もユーザー操作を起点に開始する。日本語音声の有無を起動時に確認し、無ければ読み上げ機能を自動でオフにする |
| ダブルタップで拡大してしまう | `touch-action: manipulation` を指定 |
| 長押しでコピーメニューが出る | `-webkit-touch-callout: none` / `user-select: none` |
| タップ時に灰色の枠が出る | `-webkit-tap-highlight-color: transparent` |
| 端末を振ってサイコロ | `DeviceMotionEvent.requestPermission()` が必要（ユーザー操作起点）。**タップで振るのを標準とし、シェイクは設定でオンにするオプション**にする |
| ゴムのようなスクロール | バトル画面はスクロールさせない（`overscroll-behavior: none` + 1画面に収める） |
| アイコン | `apple-touch-icon`（180×180）を用意。manifest だけでは反映されない |
| ピックの写真をとる | `<input type="file" accept="image/*">` を使う（§10.5）。`getUserMedia` は権限まわりが面倒なので使わない。撮影後は必ず縮小してから保存する |

### 9.5 配布方法

- 静的ファイルのみなので、**Cloudflare Pages / Netlify / GitHub Pages** などに無料で置ける。PWA には **HTTPS が必須**だが、いずれも標準で対応。
- 家族に渡すときは **URL を送るだけ**。受け取った側が Safari で開き、共有ボタン →「ホーム画面に追加」で完了。
- App Store の審査・年会費・アップデート申請はいずれも不要。修正したら再デプロイするだけで次回起動時に反映される。

## 10. データ管理（ずかんデータベース）

一度登録したピックは端末のデータベースに永続保存し、**次回以降は選ぶだけ**にする。

### 10.1 なぜ IndexedDB か

| 選択肢 | 判断 |
| --- | --- |
| localStorage | ✕ 容量が約5MBで、ピックの写真を持つと足りない。文字列しか保存できず、Blob を扱えない |
| **IndexedDB（採用）** | ○ 容量が大きく写真（Blob）をそのまま保存できる。索引付き検索・並べ替えができる。オフラインで動き、iOS Safari でも使える |
| サーバー上のDB | ✕ 不採用。**複数端末での共有は不要**とのことなので、通信も個人情報も持たない設計を優先する |

薄いラッパーとして [Dexie.js](https://dexie.org/) を使う（IndexedDB の生 API は冗長で扱いにくいため）。

### 10.2 スキーマ

```ts
// db.ts
import Dexie, { Table } from 'dexie';

class PickBattleDB extends Dexie {
  picks!: Table<Pick, string>;
  teamPresets!: Table<TeamPreset, string>;
  settings!: Table<{ key: string; value: unknown }, string>;
  battleLogs!: Table<BattleLog, number>;

  constructor() {
    super('pickbattle');
    this.version(1).stores({
      picks: 'id, name, type, energy, useCount, updatedAt',
      teamPresets: 'id, updatedAt',
      settings: 'key',
      battleLogs: '++id, finishedAt',
    });
  }
}
export const db = new PickBattleDB();
```

| テーブル | 内容 | 想定件数 |
| --- | --- | --- |
| `picks` | 登録済みピック | 20〜50件 |
| `teamPresets` | おきにいりチーム | 〜10件 |
| `settings` | §4 の各設定 | 数件 |
| `battleLogs` | バトル結果の履歴（将来の「きろく」画面用） | 直近100件で打ち切り |

**スキーマ変更は必ず `version(n+1)` を足して行う。** 既存の登録データを消さずにアプリを更新できることを保証する（登録し直しは保護者にとって最大の苦痛のため）。

### 10.3 リポジトリ層

UI とドメインは IndexedDB を直接触らず、この interface 越しに使う。

```ts
interface PickRepository {
  list(sort?: 'useCount' | 'name' | 'energy' | 'createdAt'): Promise<Pick[]>;
  get(id: string): Promise<Pick | undefined>;
  save(pick: Pick): Promise<void>;
  remove(id: string): Promise<void>;
  incrementUseCount(ids: string[]): Promise<void>;  // バトル開始時に呼ぶ
}

interface BackupService {
  export(): Promise<Blob>;        // 全テーブルを JSON 化（写真は base64）
  import(file: File): Promise<void>;
}
```

### 10.4 バックアップ（必須）

§9.2 のとおり、iOS ではデータが消える可能性をゼロにはできない。設定画面（S-10）に以下を必ず用意する。

- **「ずかんを かきだす」** — 全データを1つの JSON ファイルとして書き出す。iPhone では「ファイル」アプリや AirDrop、メール添付で保管できる。
- **「ずかんを よみこむ」** — JSON ファイルを選んで復元。既存データとの重複は `id` で判定し、「上書き」か「追加」を選ばせる。
- 10件登録した時点で、保護者に一度だけバックアップを促すメッセージを出す。

### 10.5 データベースの更新

スキーマを変えるときは、かならず `version(n+1)` を足す。
登録し直しは保護者にとって最大の苦痛なので、**既存のデータを消さずに**アプリを更新できることを保証する。

| 版 | 内容 |
| --- | --- |
| v1 | picks / teamPresets / settings / battleLogs |
| v2 | 写真の機能をやめたので、保存ずみの写真を消して容量を返す。なまえ・タイプ・エネルギー値・かげ はそのまま残る |

### 10.6 ピック登録の負担を減らす工夫

20枚の初回登録が最初のハードルになるため、以下を用意する。

- 入力項目は少なく（なまえ / タイプ / エネルギー値 / メガシンカ可否 / かげの かたち）。かげの かたち は任意。
- タイプは18色のボタンから選ぶだけ（キーボード入力なし）。
- エネルギー値はテンキー + 「150 / 200 / 250 / 300 / 350」のクイック選択ボタン。
- 「とうろくして つづける」ボタンで、連続登録時に一覧へ戻らない。

## 11. 技術構成

| 項目 | 選定 | 理由 |
| --- | --- | --- |
| 形態 | **PWA（ホーム画面に追加する Web アプリ）** | App Store 不要。iPhone で全画面アプリとして動く（§9） |

| 通信 | なし（完全オフライン） | 子ども向けアプリとして、個人情報も通信も持たない |
| 音声 | Web Audio API + Web Speech API | 効果音と読み上げ |
| テスト | Vitest（+ fake-indexeddb） | ダメージ計算・つかれ・メガシンカ・勝敗・DBマイグレーションはユニットテスト必須 |
| ホスティング | Cloudflare Pages 等の静的ホスティング | 無料・HTTPS 標準対応 |

| **P4: 園児向け仕上げ** | 音・読み上げ・アニメーション・ひらがな徹底・タップ領域・受け渡し画面 | **園児に実際に遊んでもらい、大人の助けなしで1バトル完走できる** |
| **P5: 調整** | 設定画面（§4）・MVP表示・目安時間の表示 | 設定を変えて手ざわりを調整できる |

P4 の完了条件は必ず**実際の子どもによるプレイテスト**で判定する。ここが本アプリの成否を分ける。

## 14. 確定事項・未決事項

### 確定した仕様

| 論点 | 決定 |
| --- | --- |
| ピックのタイプ | **1つだけ**記載されているため、複合タイプは考慮しない |
| 複数端末でのずかん共有 | **不要**。1端末 + バックアップファイルでの復旧のみ対応する |
| 動作環境 | 親の iPhone 1台。App Store を使わず PWA として配布する |

### 未決事項

| # | 論点 | 現時点の案 |
| --- | --- | --- |
| Q-1 | ダメージばいりつのデフォルト | ×20。実際に遊んでみて長ければ設定で ×30 に変更 |
| Q-2 | ばつぐんボーナスのデフォルト | +20。「タイプを狙う意味がない」と感じたら設定で +40 に（§5.3） |
